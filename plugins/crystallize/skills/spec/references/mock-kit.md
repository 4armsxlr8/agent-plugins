# モックキット (mock kit) — 正本仕様

Step 2 のラウンドシート兼 Step 3 の反応用モックの**唯一の正本**。SKILL.md 側には案数の判定規則とこのファイルへのポインタだけを置き、端末フレーム・切替バー・状態スロット・調整パネル・回答パネル・並置の作法はすべてここで定義する。回答の貼り戻しの形は `reply-format.md`。

**HTML/CSS/JS の実体はこの md にはない** — 同じスキル配下の `assets/mock-kit.html` が実体で、単体でブラウザに開ける見本を兼ねている (ダミーの2案・3種のフレーム・5つの状態・動く調整パネル・2 問の回答パネル)。テンプレートを md のコードフェンスに閉じ込めると、ブラウザで開いて検証できず、無改変で貼られたかも検算できない。

## なぜ正本を固定するか

正本があるのは従来 調整パネルだけで、端末フレーム・案の並べ方・案の切替は毎回即興だった。即興は (1) ユーザーが案を行き来するたびに操作を学び直す、(2) 案ごとに縮小率やフレーム幅が違って比較が成立しない、(3) 「1案1ファイル」でタブが増え、案の行き来が開き直しになる — の3点で認識合わせを遅らせる。キットの正本を文面ではなく**実物のファイル**で持ち、モック作成サブエージェントにはそれを複製させる (spec に書く「見た目の正本」は別の語で、そのタスクで決めた UI の確定案と値を指す)。

## 契約 — 2層 (どこまで無改変か)

| 層 | 対象 | 扱い |
|---|---|---|
| **無改変層** | `assets/mock-kit.html` の `<!-- CZ-KIT:STYLE:BEGIN 〜 END -->` / `CZ-KIT:MARKUP` / `CZ-KIT:SCRIPT` の3ブロック | 一字も変えない。順序も動かさない |
| **スロット層** | `<!-- スロット: … ここから 〜 ここまで -->` で囲まれた3ブロック (モック専用スタイル / 案 (variant) / TWEAKS・applyTweaks・ROUND・QUESTIONS) | ここだけを書き換える。見本の中身は捨ててよい |

無改変層が本当に無改変かは機械で検算できる (親がモックを受け取ったときに1回走らせる):

```bash
KIT=<spec スキルの Base directory>/assets/mock-kit.html   # 親が Skill 本文の先頭「Base directory for this skill」から組み立てた絶対パス
MOCK=docs/crystallize/specs/<slug>/mock.html
for b in STYLE MARKUP SCRIPT; do
  a=$(sed -n "/CZ-KIT:$b:BEGIN/,/CZ-KIT:$b:END/p" "$KIT"  | shasum | cut -d' ' -f1)
  m=$(sed -n "/CZ-KIT:$b:BEGIN/,/CZ-KIT:$b:END/p" "$MOCK" | shasum | cut -d' ' -f1)
  if [ "$a" = "$m" ]; then echo "$b: 一致"; else echo "$b: 改変あり"; fi
done

# スロット層が空でないことの検算 (無改変層が一致していても、中身が空なら見るものが無い)
grep -c 'data-variant=' "$MOCK"       # 1以上 (0 なら案が入っていない。CSS セレクタの行も数えるので下限だけ見る)
grep -c 'data-state=' "$MOCK"         # 1以上 (0 なら状態スロットが無い)
grep -c 'class="cz-frame-viewport"' "$MOCK"  # 全案のフレーム数の合計と一致すること (合わなければ入れ忘れ)
grep -c 'const ROUND' "$MOCK"; grep -c 'const QUESTIONS' "$MOCK"  # どちらも 1 (0 なら回答パネルが出ず、貼り戻しの 1 行目が作れない)
```

案が 0 のシート (見た目のないラウンド) では `data-variant` / `data-state` / フレームの検算は 0 でよい — 回答パネルだけが出る。

部品が足りないと感じたら即興で足さず、`assets/mock-kit.html` への追記として提案する — 正本の外に生まれた部品は次のモックで消える。無改変層はキットの版が上がると変わる (0.6.0 で回答パネルが入り、その後 調整パネルが右下のフローティングから左端のサイドバーになった) ので、古い版で作った既存の mock.html はこの検算で「改変あり」になる — 改変ではなく版の差。ラウンドを続けるなら新しいキットにスロット層を移し替える。

## ファイルと禁則

- **1タスク1ファイル** `docs/crystallize/specs/<slug>/mock.html`。案ごとに別ファイルを作らない
- **外部 CDN・外部フォント・外部画像を参照しない** — オフラインや別マシンで開いた瞬間に壊れる。CSS/JS/画像はすべてインライン (SVG 直書き・base64)
- **バックエンドや実データに配線しない** — 繋いだ瞬間に「実装禁止」が崩れ、捨てるコストが生まれて反応が歪む。ダミーデータの静的 HTML で足りる (ダミー配列から行を生成するインライン JS は配線に当たらない)
- ブラウザには `file://` で開く前提。`localStorage` や fetch に依存させない — 回答パネルの下書き保存は try/catch で包んだ任意の便利機能で、`localStorage` が無くても回答は作れる。この線 (依存しないが、使えるなら使う) を越えない
- `crypto.randomUUID` を使わない — `file://` 以外で開かれると undefined になり全滅する。id・キーは固定文字列でよい

## 案数の判定規則

| 論点の種類 | 案数 | 例 |
|---|---|---|
| 値・程度の論点 (間隔・件数・色・速度) | **1案 + 調整パネル** | カードの余白をどれくらいにするか |
| 構造の論点 (レイアウト・情報階層・主要操作) が1つ | **2案** (対立する2構造) | 一覧を縦リストにするかグリッドにするか |
| 構造の論点が複数、または方向性そのものが未定 | **3案** (上限) | 新規画面の方向性 |

この表の正本は `spec/SKILL.md` Step 3。改訂するときは両方を揃える。

- **3案を既定にしない**。親は委任前に「N案。分けたい論点: …」を1行書く。書けない案は作らない — 何を分けているか言えない案は、ユーザーに「どれが好きか」しか聞けず、好みは反応として使えない
- **案は構造的に違うこと**。色・文言だけの違いは案ではない (同じ構造の色違いは調整パネルの仕事)。できあがった案が似すぎていたら「カードグリッド禁止」のような制約を1つ足して描き直させる
- 最も価値のある反応は「B のヘッダと C のサイドバー」という混成。案は単一選択のためではなく、部品の取り合わせを引き出すために出す

## 案 (variant) の書き方

```html
<section class="cz-variant" data-variant="A" data-variant-name="縦リスト">
  <div class="cz-frame-row"> … フレーム … </div>
</section>
```

- `data-variant` は A / B / C。`data-variant-name` は構造を表す短い名前 (「縦リスト」「カードグリッド + 詳細」)。バーにそのまま出る
- 切替は3系統がキット側で動く: 画面下中央のバー (◀ 案名 ▶) / 矢印キー ← → で循環 / URL hash `#variant=B`。hash はリロードしても復元し、そのままユーザーに送れる (ローカルファイルなので search param ではなく hash)
- 矢印キーは input・textarea・select・contenteditable にフォーカスがあるときと修飾キー併用時は横取りしない — 数値入力とスライダー操作を壊さないため
- 案が1つのときはバーの送りボタンが自動で消える
- **案ごとの CSS は `.cz-variant[data-variant="B"] …` の配下に閉じる** — 漏れると案どうしが似てしまい、構造を分けた意味が消える

## 端末フレームと並置の作法

| 種別 | 寸法 | バーのラベル |
|---|---|---|
| phone | 390 × 844 | スマホ |
| tablet | 820 × 1180 | タブレット |
| desktop | 1280 × 800 | デスクトップ |

```html
<div class="cz-frame-row">
  <div class="cz-frame">
    <div class="cz-frame-label">一覧</div>
    <div class="cz-frame-shell">
      <div class="cz-frame-viewport"> … モックの中身 … </div>
    </div>
  </div>
</div>
```

- フレームはニュートラルな枠線だけ。ノッチ・スピーカー・OS のステータスバーなどの装飾は描かない — 装飾は評価対象のデザインと混ざる
- **1行に並べるフレームは最大3**。4枚目は CSS が必ず折り返す
- **縮小率は全フレーム共通**。キットは「1枚が画面幅に収まる率」まで下げ、それ以上は下げない。横幅が足りなければ折り返す — 並べたいから縮めると、案ごとの情報密度の比較ができなくなる。現在の寸法と縮小率はバー右端に出る
- ラベルはフレーム上部の固定位置 (`.cz-frame-label`)。中身の上に重ねない
- **端末幅への反応は `@media` ではなく `@container` で書く** — フレームは縮小表示された div で、window の幅は端末の幅を表さない。`.cz-frame-viewport` が `container-type: inline-size` を張っているので `@container (min-width: 700px) { … }` がフレーム幅で効く
- モック内の `position: fixed` はフレームの中に閉じる (`transform` を持つ祖先が包含ブロックになる)。下部ナビや FAB を端末の中に固定できる — 直そうとしないこと

## 状態スロット

受け入れ基準の境界に対応する状態を、静的な markup で持たせてバーから切り替える。

```html
<div data-state="empty"> … </div>
<div data-state="many"> … </div>
```

| キー | バーの表示 | 使いどころ |
|---|---|---|
| `empty` | 空 | 0件・未選択・初回 |
| `one` | 1件 | 1件しかないときのレイアウト崩れ |
| `many` | 多数 | 通常運用の密度 |
| `limit` | 上限 | 上限到達時の告知・打ち切り |
| `error` | エラー | 失敗・オフライン |

- **案ごとに最低 `empty` と `many` を持つ**。空と多数は「見れば分かる」差が最も大きく、受け入れ基準の境界そのもの
- 表示の既定は `many` (空の画面が第一印象になるとモックが壊れて見える)。ボタンの並び順は上の表の順に固定され、案を切り替えても同じ状態が選ばれたまま残る (同じ状態で案を見比べるため)
- キーはこの5つから選ぶ。独自キーも動くがバーには生のキー名が出る
- `[data-state]` を入れ子にしない。キットは同じ案の中の `[data-state]` を総なめして表示・非表示を切り替えるので、入れ子だと親子で判定が競合する
- 状態の出し分けは `data-state` に任せ、JS で状態を切り替える仕組みを自作しない (「多数」の中身をダミー配列から生成するのは可)

## 調整パネル

サイズ・間隔・色・速度・件数・閾値など「見ながら値を決めたい」プロパティは、質問で往復せずパネルで決めさせる。

- **`TWEAKS` 宣言**: パネルはこの宣言だけから自動生成される。コントロールの markup を手書きしない
  - `{ key: { label, type, value, min, max, step, unit, options } }`
  - `type` は `range` | `number` | `color` | `select` の4種。`options` は `select` のみ (`[{value, label}]`)
  - キー名は lowerCamelCase の挙動語彙 (例: `cardGap`, `accentColor`, `itemCount`)
  - `TWEAKS` が空ならパネルもバーの「調整」ボタンも自動で消える — 調整項目のないモックに空のパネルを出さない
- **`applyTweaks(values)`**: モック側が実装する唯一の接続点。flat な `{key: value}` を受け取り DOM / スタイルに反映する。**冪等に書く** — 初期表示のほか、案の切替・状態の切替のたびに呼ばれる
- **JSON 契約**: flat な `{key: value}` のみ。ネスト・メタ情報を入れない。「設定をコピー」は `navigator.clipboard` へ書き、**同じ JSON をパネル内のテキスト欄にも常時表示**する (clipboard が使えない環境のフォールバック)。同じ欄に JSON を貼って「取り込み」を押すと値が適用される。範囲外の数値は min/max へ丸め、未知のキーと不正な値は無視して欄の下に理由を出す
- **値は案をまたいで保持する** — 案 A で決めた間隔のまま案 B を見られる
- **置き場**: 画面左端に張り付くサイドバーで、バーの「調整」ボタンを押すと左からスライドして入る。開いている間はステージとバーがパネルの幅ぶん右へ寄り、縮小率もそれを勘定に入れる — パネルが絵を覆ったら「見ながら値を決める」が崩れる。幅の既定は CSS 変数 `--cz-tweak-width` の 1 箇所で決まり、パネル右端のつまみをドラッグして変えられる (ダブルクリックで既定に戻る。変えた幅はブラウザに残り、次に開いたシートでも同じ幅になる)
- **既定は畳んだ状態**。バーの「調整」ボタンで開く — 開いた状態で出すと第一印象がパネル込みの画面になり、絵より先に値の一覧を読ませることになる
- **スタイル隔離**: class は全て `cz-tweak-` プレフィックス、素の要素セレクタは書かない、配色はモックのデザイン方向と無関係なニュートラルな「ツールの見た目」に固定。パネルはモックのデザイン評価を汚染してはならない

## 回答パネル (ラウンドシートの答える場所)

ラウンドの問いを絵と同じ画面に置き、回答を固定形テキスト (`reply-format.md`) で持ち帰らせる部品。ターミナルの選択肢ダイアログに戻さない — 選ぶ瞬間に絵が画面に無くなる。

- **`ROUND` 宣言**: `{ label: '<spec の slug>', round: <ラウンド番号> }`。貼り戻しの 1 行目と下書きキー (`cz-answer-<label>-r<round>`) に使う。**ラウンドをまたぐたびに `round` を進める** — 進めないと前のラウンドの下書きが復元される
- **`QUESTIONS` 宣言**: パネルはこの配列だけから自動生成される。markup を手書きしない
  - `[{ id, title, question, premise, recommended, reason, options: [{ id, label, gain, loss, variant?, rejected? }] }]`
  - `title` = 問いの題 1 行、`question` = 挙動の選択肢として書いた質問文、`premise` = 前提 (違っていたら前提側を撃ってもらう)、`gain` / `loss` = 選ぶと得られる / 失われる挙動 (`loss` は否定形で書く)、`recommended` = 推奨する選択肢の `id`、`reason` = 推奨の理由 1 文 (バッジの横に出る。理由が無いと既定選択をただ追認させることになる)。spec スキルの質問フォーマット 4 行との対応はこのとおりで、`question-round-<n>.md` はここから機械的に起こす
  - `variant` (任意) = その選択肢が対応する案の `data-variant`。**選んだ瞬間にステージがその案に切り替わる** — 選ぶときに絵が見えている状態を作る部品で、案を選ばせる問いには必ず付ける。案の `data-variant` は親が決めてモック作成側に渡す (綴りが食い違うと黙って無視される)
  - `rejected: true` (任意) = 前のラウンドで落ちた選択肢。取り消し線で残り、選べない。決まった問いを絞って問い直すときに使う (問いごと消すなら不要)
  - 選択肢に「その他」を置かない。別の案は「全体へのコメント」に書いてもらう
  - `QUESTIONS` が空 `[]` でもパネルは出る (コメント欄と生成ボタンだけ。問いの無いラウンドでも、見ていた案・調整パネルの値・コメントの貼り戻しは要る)。消えるのは `ROUND` が未定義のときだけ
  - `id` は問いごとに一意。重複すると 1 グループに融合して片方しか答えられないので、kit は 2 つ目以降を描画せず欄の下に理由を出す
- **推奨は既定で選ばれている**。各問いに「選ばない (お任せに戻す)」があり、外した問いは `(未選択 = お任せ = 推奨 <id>)` として戻る。各問いに補足 1 行、末尾に全体へのコメント (複数行)
- **[貼り付ける文章を作る]**: `reply-format.md` の固定形を組み立て、`navigator.clipboard` へ書き、**同じテキストをパネル内の欄にも常時表示**する (clipboard が使えない環境のフォールバック。調整パネルの JSON 欄と同じ考え方)。貼り戻しには「見ていた案・状態・端末」と `TWEAKS` の最終値 (1 行 JSON) が自動で含まれる — モックの反応を口頭に頼らない
- **置き場**: 案が 1 つ以上あるときは画面右端に張り付くサイドパネルで、バーの「回答 (N 問)」を押すと右からスライドして入る (既定は画面外に畳まれている — 第一印象は絵であって問いではない)。開いている間はステージとバーがパネルの幅ぶん左へ寄り、縮小率もそれを勘定に入れる (調整パネルを同時に開いていればステージは両側から寄る) — パネルが絵を覆ったら「選ぶ瞬間に絵が見えている」が崩れる。幅の既定は CSS 変数 `--cz-answer-width` の 1 箇所で決まり、パネル左端のつまみをドラッグして変えられる (ダブルクリックで既定に戻る。変えた幅はブラウザに残り、次に開いたシートでも同じ幅になる)。案が 0 のときはステージの位置にインラインで、既定で開いた状態で出る (バーの案・端末・寸法の表示も消える)
- **推奨が `rejected` の選択肢を指していたら** kit は欄の下に警告を出し、その問いを推奨なしの `(未選択 = お任せ)` として戻す — 出題側の誤りで不採用の案が確定するのを防ぐ
- **スタイル隔離**: class は全て `cz-answer-` プレフィックス、素の要素セレクタは書かない、配色は調整パネルと同じニュートラルな「ツールの見た目」。矢印キーの横取りはパネル内の入力欄でも起きない

## 一貫性の2軸 (担保する場所が違う)

| 軸 | 内容 | 担保する場所 |
|---|---|---|
| 構造の一貫性 | フレーム・切替バー・状態・パネルの見た目と操作、JSON 形式が全モック・全セッションで同じ | `assets/mock-kit.html` の無改変層 |
| タスク内の一貫性 | 同一タスクの複数案で、同じプロパティに同じキー・同じ range・同じ単位。同じ状態キー | **親の指示** — 親が TWEAKS キー一覧 (キー名・型・range・単位・初期値) と状態キーを先に決め、全モック作成サブエージェントに**同一のものを**渡す |

正本ファイルだけではタスク内の一貫性は担保されない — キー一覧を各サブエージェントに任せると、パネルは個々に綺麗でも互いに比較不能になる。

## 埋め込み手順 (モック作成サブエージェント向け)

1. `assets/mock-kit.html` を丸ごと複製して出発点にする: `cp <親から渡された mock-kit.html の絶対パス> docs/crystallize/specs/<slug>/mock.html` (親は spec スキル本文の先頭「Base directory for this skill」を起点に `assets/mock-kit.html` の絶対パスを組み立てて渡す。サブエージェントは親の cwd もスキルの base directory も知らない)
2. **スロット層の3ブロックだけ**を書き換える
   - `<style id="cz-mock-style">` — モックのスタイル。class には `demo-` のような自前のプレフィックスを付け、`cz-` と混ぜない。素の要素セレクタ (`body {…}`, `button {…}`) を書かない (キットの外枠を壊す)
   - `<main class="cz-stage">` の中の `.cz-variant` — 案・フレーム・状態
   - `<script id="cz-mock-script">` — `TWEAKS` を**親から渡されたキー一覧どおりに**定義し (勝手にキーを増減・改名しない。足したい項目があれば親に返して全案へ同時に反映してもらう)、`applyTweaks` を実装する。**`ROUND` と `QUESTIONS` は親が書く** — 渡されたものをそのまま置き、無ければ空配列 `[]` と親から渡された `ROUND` を置く。問いを自分で足さない (出題は親の仕事で、試問と監査を通っていない問いが混ざる)
3. **ブラウザで開かない** — シートを開くのは親が試問のあとに 1 回だけ (先に開くとタブが 2 枚になり、試問前の版をユーザーが見る)。代わりに、スロット層の `<script>` を抜き出して `node --check` にかけ、構文エラーが無いことを確かめる。動作の確認 (案・フレーム・状態の切替、パネルの反映、コンソールエラーの有無) は親が開いた 1 回で行う
4. 上の検算コマンドで無改変層が一致することを確かめてから親に返す
5. スロット層の宣言 (`TWEAKS` / `applyTweaks` / `ROUND` / `QUESTIONS`) は途中で例外を投げない形で書く — キットは宣言の取得を例外に耐える形にしてあるが、スロット層が途中で落ちると宣言の一部が未定義になり、パネルが出ない

### 変えてよい / 変えてはいけない

| 対象 | 可否 |
|---|---|
| `cz-mock-style` / `.cz-variant` の中身 / `TWEAKS` / `applyTweaks` | 変える (ここがモック) |
| `ROUND` / `QUESTIONS` | 親が書く (サブエージェントは渡されたものを置くだけ) |
| `<title>` | 変えてよい |
| `CZ-KIT:STYLE` / `CZ-KIT:MARKUP` / `CZ-KIT:SCRIPT` の3ブロック | 変えない |
| `cz-` で始まる class・id・`data-variant` / `data-variant-name` / `data-state` の属性名 | 変えない (キットの JS が参照する) |
| フレームの寸法・状態キーの語彙・バーの文言 | 変えない (揃っていることが比較の前提) |

## Gotchas

- **3案を惰性で作らない** — 案数は論点の種類が決める。値の論点に3案を出すと、ユーザーは構造を選ばされていると誤解する
- **案が似すぎたら作り直す** — 「どちらでもいい」と言われた案の組は、分けたい論点が構造に現れていない。制約を足して描き直す
- **ステージは JS の初期化が終わるまで非表示** — 全案・全状態が一瞬同時に見えるのを防ぐため。開いて白いままならコンソールを見る (スロット層の JS の記述ミスが最有力)
- **モックの CSS でキットを上書きしない** — `* { }` や素の要素セレクタはフレームの外枠にも届く。`demo-` のような自前プレフィックスの配下に閉じる
- **フレームの中に本物の配線をしない** — 禁止対象はバックエンドと実データへの接続。ダミーデータを動かすインライン JS はこれに当たらない
- **モックで決めたことは実機で覆りうる** — spec に転記するときは「(モック確定・実機で再確認)」の印を付ける。触感が本物と違うのは前提で、覆ったら改訂として淡々と処理する
- **既存画面の改修では現状の再現を先頭の案にする** — `data-variant-name="現状"`。スクショの data URI か DOM 再現で現物に忠実に。変更は次の案以降に差分として描き、変わる箇所を赤系、現状を無彩色にする。現物と乖離したモックへの反応は現状への反応として使えない
- **ラウンドが終わったら決定をシートに焼き込む** (親が行う) — 確定案に「(確定)」を付けて `<section>` の先頭へ、`TWEAKS` の `value` を最後の貼り戻しの `調整パネル:` の値に、不確定案に `data-rejected` と「(不採用)」、`QUESTIONS` を `[]` に。探索状態 (複数案が同格・値が初期値のまま) で残すと、後から開いた実装者がどの案と値を写せばよいか分からない。spec の「見た目の正本」節はこの焼き込み済みのシートを指す
- **前のラウンドで捨てた案は消さず取り消し線で残す** — `<section class="cz-variant" data-rejected>` と `data-variant-name="(不採用) …"`。「これは前に落とした案か」を人の記憶に頼らせない。バーには不採用の印つきで出る
