# タスクの期限を日付で扱い、期限切れかどうかを判定できるようにする

## 使う人と場面
- ジョブストーリー: タスク一覧を表示する処理を書くとき、期限切れのタスクと期限までの残り日数をライブラリから受け取りたい。そうすれば画面ごとに日付計算を書かずに済む
- 使う人: このライブラリを使うアプリ開発者 / 場面: タスク一覧の表示処理を書いている / やり遂げたいこと: 期限切れの判定と残り日数を得る / 今のやり方: 画面ごとに日付の引き算を書いている

## 課題
期限を扱う関数がないため、呼び出し側ごとに日付の解釈と比較を書き、同じ日の扱いが画面によって食い違う。

## 解決
期限の文字列を日付に変換する関数、期限切れかを判定する関数、期限までの日数を返す関数を `tasks.due` モジュールに用意する。

## 要件
- `tasks.due.parse_due(text)` は `YYYY-MM-DD` 形式の文字列を受け取り、`datetime.date` を返す。形式が違う文字列と、暦に存在しない日付は `ValueError` を送出する
- `tasks.due.is_overdue(due_at, today)` は期限 `due_at` (`datetime.date` または `None`) と今日の日付 `today` (`datetime.date`) を受け取り、期限の日を過ぎていれば `True` を返す = 期限当日はまだ期限切れではない。期限のないタスク (`due_at` が `None`) は `False` を返す
- `tasks.due.days_until_due(due_at, today)` は期限 `due_at` (`datetime.date`) までの日数を `int` で返す。期限を過ぎていれば負の数を返す = 0 に丸めない

## 非機能要件
- 標準ライブラリのみを使う

## 見た目の正本
- キャンバス: 該当なし

## 受け入れ基準 (テストケース表)
| ID | seam | ケース | 期待結果 |
|---|---|---|---|
| AC-1 | `parse_due` | `"2026-11-01"` | `date(2026, 11, 1)` |
| AC-2 | `parse_due` | `"2026/11/01"` (形式違い) | `ValueError` |
| AC-3 | `parse_due` | `"2026-02-30"` (暦に存在しない日) | `ValueError` |
| AC-4 | `is_overdue` | 期限 `2026-10-31`、今日 `2026-11-01` | `True` |
| AC-5 | `is_overdue` | 期限 `2026-11-01`、今日 `2026-11-01` (当日) | `False` |
| AC-6 | `is_overdue` | 期限 `None`、今日 `2026-11-01` (期限なし) | `False` |
| AC-7 | `days_until_due` | 期限 `2026-11-05`、今日 `2026-11-01` | `4` |
| AC-8 | `days_until_due` | 期限 `2026-10-30`、今日 `2026-11-01` (過ぎている) | `-2` |

テストしないと決めたもの:
- `days_until_due` に `None` を渡した場合 — 期限のないタスクの残り日数は呼び出し側が尋ねない契約であり、扱いを決めない
- 時刻を含む文字列 — 期限は日単位であり、書式上 AC-2 と同じ経路で弾かれる

実機確認に委ねる基準 (UI・見た目など TDD 対象外で挙動ゲートに委ねるもの):
- なし

## スコープ外
- タスクの保存と一覧の表示
- タイムゾーンの扱い (`today` は呼び出し側が決める)

## 用語
