# 視覚調整 (錯視補正)

数値上の一致と見た目の一致は別物で、美しい UI は数値をわざと少しずらして作られている。このスキルは、そのズレを「どこに・どちら向きに・どれだけ」入れるかの初期値と、入れたズレを次の整形で消されないための書き方をまとめたリファレンス。

- **Input**: 余白・色・配置を決めようとしている UI (HTML モック / コンポーネント / SVG アイコン)、または既存 UI の「揃っていない数値」
- **Output**: 名前付きトークンとして書き込まれた補正値と、その理由コメント。確定は人間の目で行う

## 最重要の 3 点

1. **揃っていない数値を見つけても、揃える前に意図を疑う** — 上余白 295px / 下余白 317px のような非対称は、錯視を打ち消すための意図であることが多い。これを 300/300 に「直す」のが、このスキルが防ぐ最大の事故
2. **補正値は必ず名前付きトークン + 理由コメントで残す** — `padding-top: 14px; padding-bottom: 16px` と裸で書くと、意図が伝わらず次のリファクタで揃え直される。`--optical-y: 1px; /* 上方距離過大の錯視の補正 */` のように、非対称が自分で意図を名乗る形にする
3. **ここにある数値は初期値であって正解ではない** — エージェントは目で確かめられない。初期値を入れ、スクリーンショットで計測し、最終値は人間の目 (crystallize のモックなら調整パネル) に委ねる

## 補正の一覧

根拠の区分: **[出典]** = 出典に数値がある / **[幾何]** = 計算で導ける / **[経験則]** = 初期値としての目安。出典の一覧は `references/sources.md`。

### 1. 光学的な上下中央 (上方距離過大の錯視)

- **対象**: 固定高さの箱の中に中身を上下中央配置する場面 — ボタン・バッジ・タグ・チップ・カードのヒーロー・モーダル見出し
- **現象**: 上にあるものは下にあるものより大きく見えるため、数値中央に置いた中身は下がって見える
- **初期値**: 中身を数値中央より少し上へ。高さ 48px 以下の小型部品は 1px [出典 chot]。大型のヒーロー領域は 上余白 ≈ 下余白 × 0.93 (実例 295px : 317px) [出典 slide]
- **書き方**: `padding-block: calc(var(--pad) - var(--optical-y)) calc(var(--pad) + var(--optical-y))`、または中身に `translateY(calc(-1 * var(--optical-y)))`
- **注意**: CSS の中央揃えは line box の中央であって字面の中央ではない。和文フォントは字面が box 内で下寄りのものが多く、必要な補正量がフォントで変わる。必ず実測してから値を決める

### 2. 色の面積効果

- **対象**: 同じブランド色を「大面積の塗り (ボタン背景・バッジ)」と「小面積の文字・線アイコン」の両方に使う場面
- **現象**: 面積が大きいほど明るい色はより明るく、暗い色はより暗く見える。小面積の文字は同じ色でも塗りより薄く弱く見える
- **初期値**: 文字・線用に塗りより 1 段暗いトークンを分ける。実例: 塗り `#298737` / 文字 `#237B31` [出典 slide]。グレーは面積差の影響が特に出やすい [出典 chot]
- **書き方**: `--brand-fill` と `--brand-ink` を別トークンにし、文字に塗りのトークンを流用しない
- **注意**: 補正後にコントラスト比 (文字 4.5:1 / UI 部品 3:1) を再確認する。暗くする方向なら通常は改善するが、明るい背景側を補正した場合は落ちうる

### 3. 重心揃え (三角形分割錯視)

- **対象**: 非対称な図形 — 再生 ▶・矢印・シェブロン・吹き出しの尾 — を円や角丸四角の中に置く場面
- **現象**: バウンディングボックスの中央に置くと、質量の多い側 (三角形なら底辺側) に寄って見える。左右 193px / 193px でも左に寄って見える [出典 slide]
- **初期値**: 図形の重心を容器の中心に合わせる。正三角形の重心は底辺から高さの 1/3 の位置なので、右向き ▶ (幅 w) はボックス中央より **w/6 だけ頂点側 (右) へ** ずらす [幾何]。任意の図形は凸包の面積重心で近似する [出典 Bjango]
- **書き方**: `translateX(calc(var(--icon-w) / 6))` をトークン化。SVG なら viewBox 内で図形をオフセットして描き、CSS 側は触らない

### 4. 形による見かけの大きさ (円・四角・細線)

- **対象**: アイコンセット、アバター (円) とボタン (四角) が並ぶ行、丸いバッジと四角いタグの混在
- **現象**: 同じ幅・高さでも円は四角より小さく見え、細い線や複雑な形の図形はさらに小さく見える
- **初期値**: 円の直径を四角の一辺の 112.84% (= √(4/π)) にすると面積が等しくなる [出典 Bjango]。Material の keyline は 24dp グリッドで 四角 18 / 円 20 / 縦長 16×20 / 横長 20×16 [出典 Material]。細線・複雑なアイコンは +5〜10% [経験則]
- **注意**: keyline 設計済みのアイコンセット (Material Symbols 等) には掛けない。二重補正になる

### 5. オーバーシュート

- **対象**: 丸い・尖った形 (円・三角・O・A・V) が平らな形 (四角・H・E) と天地を揃えて並ぶ場面
- **現象**: 丸・尖った形は平らな辺より縮んで見え、同じ高さに揃えると小さく見える
- **初期値**: 丸・尖った形を天地 1〜3% はみ出させる [経験則]。書体は既に補正済み (「10」の 0 がガイド線をはみ出す [出典 slide]) なので、対象は UI 部品の形状。丸いアバターやチップを隣の四角ボタンより 2% 程度大きくするところから始める

### 6. 密度と重心 (写真と文字)

- **対象**: 密度の異なるブロック — 写真や単色面と、本文テキスト — が同じ左右マージンで縦に並ぶ場面
- **現象**: 文字を敷き詰めたブロックは重心が外に出るため、同じ数値マージンでも本文の方が外へ張り出して見える [出典 slide]
- **初期値**: 本文側のマージンを写真側より +4〜8% 広げる、または写真側をわずかにブリードさせる [経験則]

### 7. ハーマングリッド

- **対象**: 暗いタイルを細い明るい間隔で規則的に並べたグリッド
- **現象**: 交点に灰色の影がちらつく
- **初期値**: 間隔を狭めるか広げる、グリッドを不規則にする、背景に色を付ける [出典 Goodpatch]

## 適用手順

1. **候補を洗い出す** — 上の「対象」列を当てて、該当箇所を列挙する。固定高さ × 中央揃え / ブランド色の文字 / 非対称アイコン in 円 / 円と四角の混在 / 密度差のあるブロックの隣接 / 暗いタイルグリッド
2. **現状を測る** — スクリーンショットを撮り、上下・左右の余白を px で計測する。デザインツール由来の SVG やフォントは既に光学補正されていることがあり、測らずに補正を足すと二重になる
3. **初期値をトークンで入れる** — 補正ごとに名前付きトークンと理由コメント。値を散らさず 1 か所に集める
4. **人間に見せて確定する** — 撮り直したスクリーンショットで比較する。crystallize の spec モック (`docs/crystallize/specs/<slug>/mock.html`) の中なら、`opticalShiftY` / `brandInk` のようなキーで TWEAKS に晒し、ユーザーがその場で動かして決められるようにする (正本は crystallize の `spec/references/mock-kit.md`)
5. **確定値を記録する** — トークン定義のそばに、何の錯視に対する補正かを一文で残す

## 直接呼ばれたとき

`/ui-craft:visual-adjustment` として引数なしで呼ばれた場合は、いま作業中の UI (直前に編集したモック / コンポーネント) に対して手順 1〜2 を行い、該当箇所と初期補正値の一覧を提示するところで止める。変更はユーザーの同意後に手順 3 以降として行う。

## Gotchas

- **「ちょっとだけ違う」をバグ扱いしない** — lint・整形・リファクタで非対称な値を揃えるのは、このスキルの目的を裏返した事故。トークン名も理由コメントもない非対称に出会ったら、揃える前に意図を確認する
- **二重補正** — フォント (字面が光学補正済み)、keyline 済みアイコンセット、デザインツールで既に光学揃えされた SVG (viewBox 内オフセット済み) に、さらに CSS で補正を足すとかえってずれる。手順 2 の計測を飛ばさない
- **中央揃えの基準を先に固定する** — `align-items: center` は line box の中央、`vertical-align: middle` は x-height の中央、SVG は viewBox の中央で、それぞれ数値中央の位置が違う。どの基準に対する補正かを決めてから値を入れる
- **数値を押し付けない** — ユーザーが「揃えて」と言ったら、揃えた場合の見え方 (下がって見える・薄く見える) を一文で伝えたうえで従う。ヒューリスティクスは初期値で、最終判断は目で見た人のもの
- **補正でコントラスト比を落とさない** — 色の面積効果の補正は明度をいじる。文字 4.5:1 / UI 部品 3:1 を補正後に再確認する
