# 文書シート (doc sheet) — 正本仕様

**画面のないタスク**のラウンドシート (Step 2) の**唯一の正本**。データモデル・API・CLI の引数と出力・バッチ/移行・状態機械・閾値やスコアリング・権限表・外部サービス連携のように、確認するものが画面ではなく表や例文であるタスクで使う。画面が 1 つでもあるタスクは `mock-kit.md` のモックキットを使う (キットは端末フレームの中に静的テキストも置ける)。**1 タスクにつきシートは 1 種類・1 ファイル**で、両方を並行して作らない。回答の貼り戻しの形は `reply-format.md`。

**HTML/CSS/JS の実体はこの md にはない** — 同じスキル配下の `assets/doc-sheet.html` が実体で、単体でブラウザに開ける見本を兼ねている (語句の暗記アプリの試行記録の保存形を例に、A/B の案がある問い・答えで例が描き分けられる問い・見るものの無い問い・値の帯・前提の帯を 1 枚で見せる)。

## なぜモックキットと分けるか

モックキットは「絵を見せて選ばせる」道具で、端末フレーム・案の切替バー・状態ボタン・左右のスライドパネルは、絵が 1 画面に 1 つしか入らないことから来ている。画面のないタスクでそれを使うと、表や JSON を端末枠に入れて縮小して読ませることになり、問いは左のパネル、見るものは中央の枠、値は右のパネルに散って、どの問いがどの表を指しているのか追えなくなる。文字の成果物は横に並べて行単位で比べられるので、切替もパネルも要らない。問いとその問いで見るものを同じ行に置く、上から読む一枚の文書にする。

## 骨格: 1 論点 = 1 帯

シートは縦に並んだ帯でできている。1 本の帯が 1 つの論点を持ち、**左に問い、右にその問いで見るもの**を置く。対応は「同じ帯の左右にある」ことだけで示す。帯の区切りは横の罫線 1 本、左右の境界は間隔だけで、縦線や色地は無い。

```
前提   質問にしていない判断        │ P1 … [異議]  P2 … [異議]
▸ これまでの決定 (n)  折りたたみ   │
Q1     <題> / 前提 / 問い          (案ごとの見るものがある問い: 帯は全幅)
       ┌ ●A 得る 失う ┐ ┌ ○B 得る 失う ┐   ← 選択肢と見るものを 1 枚のカードにして案の数だけ並べる。切り替えない
       │ A の見るもの │ │ B の見るもの │      幅が足りなければ 1 列。得失の段と見るものの段はカード間で高さを揃える
       └─────────────┘ └─────────────┘
       推奨 / 補足
Q2     <題>                        │ 答えで描き分けられる 1 つの表
Q3     <題> (見るものが無い問い)    — 右の欄を持たず 1 列で出る
値     数値の論点                   │ 値で計算し直す例
       初回の間隔 [2] ─●─ 効く例: Q1 値
全体へのコメント / [貼り付ける文章を作る] / 貼る文章
```

- **問いの帯の右側には、その問いを決めるのに見なければならないものだけ**を置く。複数の問いが同じ例を使うときも、帯ごとに必要な切り口だけを同じ `MODEL` から描く (見本では同じ試行の列を、Q1 は保存形、Q2 は提案までの回数、値の帯は期日の表として描いている)。1 つの大きな表を共有して「どこを見ればよいか」を読者に探させない。
- **見るものが無い問い** (文章だけで決める論点) は右の欄を持たず、問いを 1 列で出す。`exhibit` も `note` も無ければ固定層が自動でそうする。無理に見るものを作らない。
- **案 A/B は切り替えずに並べる**。案ごとの見るもの (`options[].exhibit`) がある問いは、選択肢 (得る・失う) とその案の見るものを 1 枚のカードにして案の数だけ横に並べる — 左の選択肢と右の列を目で対応させる手間を無くすため。選んでいる案のカードに枠が付き、カードのどこを押しても選べる。カードの中の字は薄くしない (読む量が多いため)。幅が足りなければ 1 列に落ちる (2 列にはしない。3 案が 2 列 + 1 列に割れると見比べにくいため)。3 案までを想定 (SKILL.md Step 3 の案数上限と同じ)。問い全体の見るもの (`exhibit`) だけの問いは、これまでどおり帯の右側に置く。
- **値 (数値・程度の論点) は問いにせず「値」の帯に置く**。左の入力欄 (数値 + スライダー) を動かすと、その値を使うすべての例が計算し直され、変わったセルが一瞬強調される。例の側には「使う値: 初回の間隔 2日」の印、入力の側には「効く例: Q1 値」のリンクが宣言から自動で出る。最終値は貼り戻しの `調整パネル:` 行に載る (行名は reply-format の契約なので、画面の部品名が「調整パネル」でなくてもこの行名を使う)。
- **前提 (質問にしていない判断) は先頭の帯**。各行に「異議」欄があり、書いた異議は貼り戻しの `全体へのコメント:` の先頭に `前提 P3 (<本文>) への異議: …` として載る。調べて確定した事実を質問にせず見せる場所で、SKILL.md の「客観的事実をユーザーに質問しない」と対になる。
- 色は「選んでいる」印の青いラジオと、選択肢の「得る:」(緑)・「失う:」(赤) の見出し語だけ。番号 (Q1 / 前提 / 値) は見出しと同じ大きさ・同じ色。配色の変数とライト / ダークの切り替え (右上の ◐、鍵は html-report と同じ `crystallize-report-theme`) は html-report の `style.css` と同じで、シートの `CZ-THEME` の範囲がそれをそのまま写している (`assets/check-theme.sh` で一致を検算する)。

## 契約 — 2 層 (どこまで無改変か)

| 層 | 対象 | 扱い |
|---|---|---|
| **無改変層** | `assets/doc-sheet.html` の `<!-- CZ-DOC:STYLE:BEGIN 〜 END -->` / `CZ-DOC:MARKUP` / `CZ-DOC:SCRIPT` の 3 ブロック | 一字も変えない。順序も動かさない |
| **スロット層** | `<!-- スロット: … ここから 〜 ここまで -->` で囲まれた `<script id="cz-doc-data">` 1 ブロック | ここだけを書き換える。見本の中身は捨ててよい |

検算は同じディレクトリの `assets/check-doc-sheet.sh` で行う (サブエージェントは返す前に、親は受け取ったときに 1 回):

```bash
sh <spec スキルの Base directory>/assets/check-doc-sheet.sh \
   <spec スキルの Base directory>/assets/doc-sheet.html docs/crystallize/specs/<slug>/sheet.html
# 親が Skill 本文の先頭「Base directory for this skill」から絶対パスを組み立ててサブエージェントに渡す
```

検算の中身は 4 つ。(1) 無改変層 3 ブロックの shasum が正本と一致するか。(2) `ROUND` / `QUESTIONS` / `DECIDED` / `MODEL` の宣言があるか。(3) スロット層の構文 (`node --check`)。(4) **`MODEL` / 各 `exhibit` / `VALUE_EXHIBITS` を既定値・最小値・最大値で実際に呼び**、例外なく `table` / `text` のブロックが返り、`uses` のキーが `TWEAKS` にあり、`QUESTIONS` と `DECIDED` の id が重複していないか。構文だけでは実行時の取り違え (行の並びの誤り、未定義参照) が最初にユーザーの画面で起きるため、(4) を省かない。固定層は描画に失敗したブロックを注記に置き換えて残りを出すので白紙にはならないが、その注記をユーザーに見せてはいけない。

部品が足りないと感じたら即興で足さず、`assets/doc-sheet.html` への追記として提案する — 正本の外に生まれた部品は次のシートで消える。無改変層は版が上がると変わるので、古い版で作った既存の `sheet.html` はこの検算で「改変あり」になる — 改変ではなく版の差。ラウンドを続けるなら新しい正本にスロット層を移し替える。

## ファイルと禁則

- **1 タスク 1 ファイル** `docs/crystallize/specs/<slug>/sheet.html`。ラウンドを重ねても同じファイルを更新する
- **外部 CDN・外部フォント・外部画像を参照しない**。CSS/JS はすべてインライン
- **バックエンドや実データに配線しない**。サンプルは定数で持ち、規則は `MODEL` に書く。ダミー配列から表を生成するのは配線に当たらない
- `file://` で開く前提。`localStorage` は下書き保存にだけ使い、無くても回答は作れる。`crypto.randomUUID` を使わない
- 見るものの型は `table` と `text` の 2 つだけ。図・グラフ・独自の描画器を足さない (8 種のタスクはこの 2 型で組める。足すのは 2 型で表せない実例が出てから)

## スロット層の宣言

すべて `<script id="cz-doc-data">` の中に書く。フィールド名は SKILL.md Step 2 の `QUESTIONS` 定義と同じで、質問監査用の `question-round-<n>.md` はここから機械的に起こせる。

| 名前 | 型 | 誰が書くか | 中身 |
|---|---|---|---|
| `ROUND` | `{label, round, final, title, lead}` | 親 | `label` = spec の slug (貼り戻しの 1 行目と下書きキーに使う)。`round` はラウンドごとに進める。`final` は決定の記録にするとき `true`。`title` はタスクの 1 行、`lead` はシート冒頭の案内 1〜2 文 |
| `PREMISES` | `[{id:'P1', text}]` | 親 | 質問にしていない判断。3〜5 個。調べて確定した事実、既存 spec や用語集から引き継ぐ決定、今回は触らない範囲 |
| `TWEAKS` | `[{key, label, unit, min, max, step, value}]` | 親 (定義)。値の既定は親 | 数値・程度の論点。`key` は lowerCamelCase の挙動語彙。**空配列なら値の帯は出ない** |
| `QUESTIONS` | `[{id, title, premise, question, recommended, reason, options, exhibit?, note?}]` | 親 (文面)。`exhibit` と `note` はサブエージェント | 今回の問い。`id` は英小文字の安定した名前 (表示番号 Qn は並び順から付く)。`options` = `[{id:'A', label, gain, loss, exhibit?, rejected?}]`。`gain` / `loss` は選ぶと得られる / 失われる挙動 (`loss` は否定形)。`recommended` は既定で選ばれて表示される。`note` は見るものの下に出る 1 行の注記 (例の読み方・省略した旨) で、`exhibit` のある問いにだけ書く (`note` だけだと右の欄が注記 1 行のために出てしまう) |
| `DECIDED` | `QUESTIONS` と同じ形 + `decided`, `round` | 親 | 前のラウンドで決まった問い。折りたたみの「これまでの決定」に読み取り専用で出る |
| `MODEL(values, pick)` | 純関数 | サブエージェント | 見るものが使うデータを計算する唯一の場所。`values` は `TWEAKS` の現在値 `{key: value}`、`pick(id)` は問いの現在の答え (未選択なら推奨)。値に依存しないタスクでも `() => ({})` を置く |
| `exhibit(m, values, pick)` | 関数 → ブロック 1 つか配列 | サブエージェント | `QUESTIONS[].exhibit` は問い全体で 1 つの見るもの (答えで描き分ける)。`options[].exhibit` は案ごとの列。ブロックは `{type:'table', title, columns, rows, hl?, note?, uses?}` か `{type:'text', title, text, note?, uses?}`。`hl` は強調する行番号の配列、`uses` は**その値を変えるとその例が実際に変わる**キーだけ (変わらない値を書くと「効く例」のリンクが嘘になる) |
| `VALUE_EXHIBITS(m, values)` | 同上 | サブエージェント | 値の帯の右側 (値を変えた効き目が最もよく見える表) |

## いつ・誰が作るか

- **第 1 ラウンドで親が正本を複製して作る**。親はスロット層の見本 (サンプル・`MODEL`・`exhibit`・`VALUE_EXHIBITS`・見本の `TWEAKS`) を**すべて捨て**、`ROUND` / `PREMISES` / `TWEAKS` (無ければ `[]`) / `QUESTIONS` の文面 / `DECIDED = []` を書く。見るものの要らない問いだけのラウンドなら、`MODEL = () => ({})`、`VALUE_EXHIBITS = () => []` を置いてこれで完成 (委任しない)
- **見るものの要る問いがあるラウンドでは、そのラウンドごとに埋め方をサブエージェントへ委任する**。渡すのは正本 2 ファイルと `check-doc-sheet.sh` の絶対パス、現在の `sheet.html` のパス、親が書いた宣言、各問いで見せたいものの 1 行 (「案ごとに同じ 4 回の試行を保存した姿」など)。サブエージェントは既存のスロット層に `MODEL` と `exhibit` を足す (宣言の文面は変えない)
- 提示後に問いを直したときは同じ `round` のまま再読み込みで確認してもらう。固定層は下書きの選択肢が存在しなくなっていれば捨てるので、選択肢を消しても壊れない

## 埋め方 (シート作成サブエージェント向け)

1. **正本を `cp` しない**。親がすでに `docs/crystallize/specs/<slug>/sheet.html` を作っている (第 1 ラウンドで正本を複製済み)。渡されたそのファイルのスロット層 (`<script id="cz-doc-data">` の中) だけを編集する。複製し直すと、親の宣言と前のラウンドの `MODEL` / `exhibit` が消える。正本 (`assets/doc-sheet.html`) の絶対パスは検算の比較元としてだけ使う
2. **スロット層だけ**を書き換える。親から渡された `ROUND` / `PREMISES` / `TWEAKS` / `QUESTIONS` の文面と `DECIDED` は**そのまま置く** (問いを自分で足さない。出題は親の仕事で、試問と監査を通っていない問いが混ざる。値の項目を足したければ親に返す)
3. 見るものが必要とするサンプル (試行の列、リクエスト、入力ファイルなど) を定数で置き、規則を `MODEL` に書く。**見るものは同じ入力に対する案ごとの結果**にする (入力を案ごとに変えると、違いが案のせいか入力のせいか読めない)。案の差を見せるために入力の途中で出来事を起こす (2 往復のあいだに 1 件追加する、3 段目で失敗させる、など) のはよいが、**同じ出来事を全案に入れる**。疑似コードは規則そのものの合意に `text` で置いてよいが、疑似コードだけで判断させず、必ずその規則で計算した結果の表を並べる
   - **ほかの問いの答えに合わせて描く**: ある問いの例の外側 (例: 応答の包み方) が別の問いの答えで変わるなら、`exhibit` の中で `pick('<その問いの id>')` を読んで描き分ける。読者は上の問いを答えた状態で下の問いを見るので、上の答えが反映されていないと例が嘘になる。ただし描き分けるのは外側だけで、この問いの論点そのものは変えない
   - **長い一覧は省略する**: `text` や `table` に 20 件を並べない。先頭 2〜3 件と末尾 1 件を出し、あいだに `… (残り 17 件)` の 1 行を置く。省略しても論点の判断に要る行 (境界の直前と直後、変わる行) は必ず残す
4. 各問いの `exhibit` を書く。**その問いを決めるのに要らないものは置かない**。要るものが無い問いには `exhibit` を書かない (1 列で出る)
5. **ブラウザで開かない** — シートを開くのは親が試問のあとに 1 回だけ
6. `check-doc-sheet.sh` を走らせ、「検算: すべて通過」を確かめてから親に返す。通らないものを返さない

## 8 種のタスクでの 1 ラウンドの組み方

各行は「Q の帯の右に並べるもの / 値の帯 / 前提の例」。

| タスク | Q の例と右に並べるもの | 値の帯 | 前提の例 |
|---|---|---|---|
| データモデル設計 | 「履歴を別表か埋め込みか」→ 案ごとに同じサンプルを保存した表 (table) / JSON (text) | 保持件数、保持日数 → サンプル行数や削除される行が変わる | 主キーは連番、論理削除しない |
| API 設計 | 「一覧をページ番号式かカーソル式か」→ 案ごとの要求と応答の往復 (text: `GET …` + JSON) を 2 往復分 | 1 ページの件数、上限 → 応答の件数と `next` が変わる | 認証はトークン、時刻は UTC |
| CLI の引数と出力 | 「失敗時に続行か即停止か」→ 案ごとの端末の実行例 (text: `$ cmd …` と出力、終了コード) | 並列数、再試行回数 → 出力の行と所要の表示が変わる | 出力は標準出力、色は付けない |
| バッチ/移行処理 | 「途中失敗で全体を戻すか、済んだ分を残すか」→ 案ごとの実行前後の表 (table 2 つ) と途中で止めたときの状態 | 1 回の処理件数、何件目で失敗させるか → どこで区切られるか、二重処理や欠落がどこに出るか | 本番の前に試行を 1 回する |
| 状態機械 | 「期限切れから再開できるか」→ 案ごとの遷移表 (table: 現在の状態 × 出来事 → 次の状態)。変わる行を `hl` | 期限の時間 → 例の時刻列の遷移が変わる | 状態は 5 つ、並行して 2 つの状態は取らない |
| 閾値・スコアリング | 「同点をどう並べるか」→ 案ごとに同じ入力 10 件の順位表 (table)。案で順位が入れ替わる行を `hl` | 閾値、重み → スコア列と合否が計算し直される | 入力は 0〜100 に揃えてある |
| 権限表 | 「編集者に削除を許すか」→ 案ごとの役割 × 操作の表 (table)。案で違うセルのある行を `hl`。列が多ければ表は横スクロール | (多くは無い。あれば招待の有効日数など) | 管理者は常に全部できる |
| 外部サービス連携 | 「相手が落ちたとき待つか諦めるか」→ 案ごとの時系列の実行ログ (text: 時刻・送信・応答・再試行) | タイムアウト秒、再試行回数、間隔 → ログの時刻と試行回数が計算し直される | 相手の応答は最大 N 秒、冪等キーを送る |

## 貼り戻しの形 (reply-format との対応)

`reply-format.md` の固定形をそのまま使う。文書シート固有の点は次のとおり。

- `見ていた案:` の行は**出ない** (案は切り替えずに並べるので「見ていた」と「選んだ」が分かれない)。したがって案の採否と見ていた案の食い違い検査は文書シートでは行わない
- **推奨は既定で選ばれて表示されるが、ユーザーが押すまでは `(未選択 = お任せ = 推奨 A)` として戻る**。押すと `A — <label>` になり、「お任せに戻す」で未選択に戻せる。モックキットは既定選択のまま `A — <label>` を出すが、文書シートでは「明示的に同意した」と「推奨に任せた」を区別できるほうを採った (どちらも推奨で確定するので読み手の処理は同じ)
- `調整パネル:` の値は値の帯の現在値 (`TWEAKS` が空なら行ごと出ない)
- 前提への異議は `全体へのコメント:` の本文の先頭に `前提 Pn (<本文>) への異議: …` として 1 行ずつ入る。本文中にユーザーが書いた `---` だけの行は `- - -` に置き換える (本文の終端が `---` のため)

## ラウンドを重ねるとき (親が行う)

1. 決まった問いを `QUESTIONS` から `DECIDED` へ移し、`decided: '<採用した選択肢の id>'` と `round: <決まったラウンド>` を付ける。採らなかった選択肢は自動で取り消し線 (不採用) になり、案の列も薄く取り消し線で残る。**消さない** (前に落とした案かどうかを記憶に頼らせない)
2. 決まった問いを絞って問い直すときは、その問いを `DECIDED` へ移さず `QUESTIONS` に残し、除外した選択肢に `rejected: true` を付ける (同じ `id` を `DECIDED` と `QUESTIONS` の両方に置かない。両方にあると固定層は `QUESTIONS` 側を生かして注意書きを出す)
3. 新しい問いを `QUESTIONS` に書き、`ROUND.round` を進める (進めないと前のラウンドの下書きが復元される)
4. `TWEAKS` の `value` を前回の貼り戻しの `調整パネル:` の値に更新する

## 決定の記録として残すとき (終了条件を満たした後、親が行う)

1. 残りの問いをすべて `DECIDED` へ移し、`QUESTIONS = []` にする
2. `TWEAKS` の `value` を最終の貼り戻しの `調整パネル:` の値に書き換える
3. `ROUND.final = true` にする。見出しが「決定の記録」になり、前提の異議欄・補足欄・お任せの表示と、末尾の回答欄 (コメント・貼り付ける文章) が消え、「これまでの決定」が開いた状態で出る
4. `final: true` のシートは下書き (localStorage) を復元も保存もせず、値の入力欄も動かせない。焼き込んだ `value` と `decided` が正本になる
5. 探索状態 (問いが残っている・値が初期値のまま) で残さない。ただし**実装者に渡るのは spec 本文であってこのシートではない** (後続の plan-create / plan-implement / code-generator は spec の「見た目の正本」節経由で `mock.html` だけを読み、`sheet.html` は読まない)。したがって、採用した案・確定した値 (`調整パネル:` の最終値) ・前提はすべて spec の「要件」「受け入れ基準」に書き写す。spec の「見た目の正本」節には「確定案: 該当なし」に続けて `決定の記録: docs/crystallize/specs/<slug>/sheet.html` と `調整パネルの最終値: {…}` の 2 行を書く (検討の経緯を辿る入口としてのみ。定義の正本は spec 本文で、改訂で値が変わったら「要件」側を直し、この行は最終ラウンド時点の記録として更新しない)

## 試問への渡し方

文書シートの見るものは `MODEL` が計算する関数で、HTML を読むだけでは表の中身が分からない。試問 (SKILL.md Step 2) のサブエージェントには、シートの絶対パスに加えて `check-doc-sheet.sh --dump` の出力 (既定値で描いた見るものの中身。問い・案ごとの題・列・行・注記が文字で出る) を渡し、弁別性の判定は `options[].exhibit` の関数本体と、それが返す `title` / `columns` / `note` の違いから行わせる。ブラウザ表示ツールがある環境では開いて見比べてよい。

## Gotchas

- **見るものを問いより先に作らない** — 問いが決まってから、その問いに要る切り口だけを描く。先に大きな表を作ると全部の問いがその表を指し、対応が読めなくなる
- **案ごとに入力を変えない** — 同じ入力に対する案ごとの結果を並べる
- **値の論点を問いにしない** — 「件数は 10 か 20 か」は値の帯で決める。問いにすると `調整パネル:` 行と二重になる
- **見るものの無い問いに飾りを置かない** — 1 列で出るのが正しい形
- **`MODEL` を副作用で書かない** — 描画のたびに `values` と `pick` から呼ばれる。同じ入力なら同じ結果になるように書く
- **前提を質問で聞き直さない** — 前提の帯は「違うなら異議を書いてもらう」場所。異議が出たら次のラウンドの問いにする
- **ラウンドが終わったら決定を焼き込む** — `final: true`、`QUESTIONS = []`、`TWEAKS` の確定値、`DECIDED` の `decided`。焼き込まないと、後から開いた人は何が決まったのか分からない
