# issue-create

会話の文脈や簡潔なメモを、構造の整った GitHub issue へ変換して起票する。リポジトリに issue テンプレートやラベルの運用があればそれに従い、無ければ新規作成しない — 起票先リポジトリの既存の設定を優先し、本スキル独自で設定を追加しない。サブエージェントは起動しない — 参照する情報が会話内にあるため、メイン会話で実行する。

## Input / Output

- **Input**: `$ARGUMENTS` = issue にしたい内容のメモ。省略時は直前の会話から対象を推定し、一行で確認を取る
- **Output**: GitHub issue (作成された URL を報告)。リポジトリの状態は変更しない (テンプレートやラベルを作成しない)

## 最重要ルール

1. **起票は対外的な操作 — 承認フェーズ (手順6) を飛ばして `gh issue create` しない**。承認前に作られた issue は削除しても通知や履歴が相手側に残り、取り消せない
2. **会話・メモに無い事実を補わない** — 推測で埋める箇所は「推測:」と明示する。必須といえる項目 (バグなら再現手順) が埋まらなければ、起票せずその項目だけ質問する
3. Web フォームと違い `gh issue create` はテンプレートの required を強制しない — **必須項目の確認と担保は本スキルで行う**

## 手順

1. 対象リポジトリを確定する (cwd の git root。曖昧なら確認)
2. リポジトリの設定や運用ルールを調べる — `.github/ISSUE_TEMPLATE/` のテンプレート (`*.yml` / `*.md`) と `gh label list` の実在ラベルを確認する
3. 種別を判定する (バグ報告 / 機能要望 / 雑務)。内容から自明でなければ、技術的な用語ではなく動作や振る舞いの言葉で確認する
4. 本文を組み立てる:
   - **テンプレートがあれば**その項目立てどおりに書く。必須項目 (required) が会話の情報だけで埋まらなければ、その項目だけ質問する
   - **無ければ**種別に応じた見出し付きの構造で書く — バグ: 再現手順 / 期待した挙動と実際の挙動 / 環境。機能要望: 背景・困りごと / 欲しい挙動 / 受け入れ基準。雑務: やること / 完了条件
   - 機能要望の**受け入れ基準は観測可能な挙動レベル**で書く (テンプレートに欄が無くても見出しとして含める — 後段の spec / plan でそのまま利用するため)
5. 重複を確認する: `gh issue list --search` で似た issue を探し、あればリンクを提示して起票するか判断を仰ぐ
6. **承認フェーズ**: 投稿される内容は地の文ではなく **AskUserQuestion の question 内に全文を埋め込んで**提示する (focus mode では AskUserQuestion で終わるターンの地の文がユーザーに見えないため、地の文での提示は届かない)。question にタイトル / 本文の全文 (要約にしない。要約と実物の差分に指摘漏れが生まれる) / ラベル (付ける場合) / 起票先リポジトリを含め、「起票する / 修正する」を確認し、修正の指摘があれば本文を直してこの手順を繰り返す。**明示的な承認が出るまで起票しない**
7. 承認を得てから `gh issue create` を実行する。`--label` は**手順2で確認した実在ラベルから内容に合うものがあるときだけ**付ける — 一覧に無いラベルは指定しない (作らない)。合うものが無ければラベルなしで起票する
8. URL を報告し、次のアクションを1行だけ案内する (着手するなら新セッションで `/spec` に issue の URL か要約を渡す)

## Gotchas

- **issue を plan にしない** — issue は課題や要望を記録する場所であり、詳細な計画書ではない。背景・欲しい挙動・受け入れ基準まで書けたら止める。詳細な検討 (見落としの探索・質問による詰めの議論・モック作成など) は spec の役割であり、起票段階で詳細化しすぎると情報の二重管理になる
- **無いラベルを `--label` に渡すと起票ごと失敗する** — 存在しないラベルを独自に作成・指定しない。ラベル体系の整備はリポジトリ管理者の役割であり、本スキルは実在するものから選ぶだけとする
- **テンプレートの必須項目は起票後には強制されない** — Web フォームと違い CLI 経由では入力チェックが行われない。必須項目に相当する内容が埋まらないまま承認フェーズへ進めない
