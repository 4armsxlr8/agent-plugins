# ui-craft

UI/UX のエッセンス——デザイナーが経験則として持っている「なんとなく美しい／なんとなく揃っていない」の判断——を、目で見ることのできないエージェントが実行できる形に翻訳したスキル集です。翻訳の中身は「数値の初期値」「トークンでの書き方」「スクリーンショットでの検証手順」の3点で、確定は常に人間の目に委ねます。スキルは今後増やしていく前提で、現在は `visual-adjustment`（錯視補正）の1本のみです。

## なぜ作ったか

エージェントに UI を作らせると、余白は数値で揃え、色はトークンで統一し、結果として「数値上は正しいのに見た目がずれている」UI ができあがります。逆方向の事故も起きます。デザイナーが意図して入れた少しのズレ——たとえば上余白 295px / 下余白 317px のような非対称——を、リファクタや整形の過程で「バグ」として揃え直してしまうのです。

数値の一致と見た目の一致は別物だという知識は、デザイナーには経験として備わっていますが、エージェントには備わっていません。かといって常にこの知識を意識させると過剰補正の原因になるため、発動条件（トリガーワードや「揃える」判断をする場面）付きで注入する形にしました。それが ui-craft です。

出典は原佑一氏（CyberAgent / Ameba）の Speaker Deck「美しいUIを作るために デザイナーが意識している ちょっとした考え方」ほか。各補正値の根拠区分と出典一覧は `skills/visual-adjustment/references/sources.md` にまとめてあります。

## スキル一覧

| スキル | 内容 |
|---|---|
| `visual-adjustment` | 錯視補正。上方距離過大の錯視 / 色の面積効果 / 三角形分割錯視（重心揃え） / 形による見かけの大きさ / オーバーシュート / 密度と重心 / ハーマングリッドの7項目について、初期値とトークンでの書き方をまとめる。発動ワードは「錯視補正」「視覚調整」。モック作成や UI 実装で余白・色・配置を「揃える」判断をする場面でも自動発動する |

## 設計上の判断

- **crystallize から分離した、手順ではなく知識のプラグイン** — crystallize は「仕様決め→実装→検証→コミット」という工程を担い、ui-craft は UI/UX のドメイン知識を担います。役割の分け方は `flutter-riverpod-guardrails`（Flutter + Riverpod のアーキテクチャ知識）と同じ側で、crystallize（工程）とは別軸です。
- **数値は正解ではなく初期値として書く** — エージェントは自分の出力を目で確かめられません。書いてある数値は「ここから始めて実測で調整する」ための初期値であり、最終確定はスクリーンショットや crystallize の調整パネルを通した人間の目に委ねます。
- **補正値は名前付きトークン + 理由コメントで残す** — 補正を裸の数値で書くと意図が伝わらず、次のリファクタで「揃っていないバグ」として直されてしまいます。`--optical-y: 1px; /* 上方距離過大の錯視の補正 */` のように、非対称そのものが意図を名乗る形で残す規則にしました。

## crystallize との関係

依存関係はなく、どちらか片方だけでも動作します。crystallize の `spec` がモックを作る場面や、`plan-implement` の UI 実装スライスで「揃える」判断が必要になったとき、description のトリガーによって自然に読み込まれる想定です。モックの中では補正値を TWEAKS（調整パネル）に晒し、ユーザーがその場で数値を動かして決められるようにします。
