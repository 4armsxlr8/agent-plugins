# デザインキャンバス — 案出しと清書

画面のあるタスクでは、claude.ai の Design 型 Artifact (アートボードを並べる面) を 2 種類使う。

- **案出しキャンバス**: spec ごとに 1 つ作る使い捨ての面。各ラウンドの案と、問いのアートボード (問いと回答欄) を置く
- **清書キャンバス**: プロジェクトに 1 つの面。spec の終了時に、確定した案だけを写す

分けるのは、案出しの絵 (落ちた案・途中の版・問い) が清書と同じ面に残ると、確定したデザインを見るときに邪魔になるため。ここに書く名前 (`project/`・`.dc.html`・`canvas.json`・`support.js`・プロトタイプリンク・`<dc-import>`・`data-props`) は 2026-10-18 と 2026-11-13 に Design 型の指示で確認したもの。アートボードのファイルの書き方そのものはここに書かず、キャンバス作成時 (または `type_url` の `read`) に Design 型が返す指示に従う。**型の指示が変わっていたら型の指示が勝つ**。例外は問いのアートボードだけ (「問いのアートボード」の節)。

## 両方に共通すること

- Design 型の `type_url` は Artifact ツールの `action: "quickstart"`, `intent: "design"`, `design_systems: false` で得る
- **セッションの最初に、そのセッションで公開するキャンバスごとに 2 回 `read` する**。(1) `action: "read"` + `url` = キャンバス: そのセッションで read も publish もしていない Artifact への publish は拒否されるため。これはページしか返さない。(2) `action: "read"` + `type_url` (url は渡さない): Design 型の指示が返る。後のセッションはこれでしか指示を取り戻せない
- デザインシステムは清書キャンバスと同じものを入れる (`design-canvas.md` に記録したもの。清書キャンバスがまだ無ければ quickstart の一覧から、プロジェクトのデザインシステムがあればそれ)。入れ方は Design 型の指示に従う
- アートボードの名前は `<slug>-R<round>-Q<n>-<選択肢 id>` (ファイルは `project/share-card-link-R5-Q1-A.dc.html`)。1 案が複数画面なら `share-card-link-R5-Q1-A-2` と続ける。`boards` の `title` には slug を除いた `R5-Q1-A` を書き、提案の案は先頭に「(提案)」を付ける (キャンバスの名札にはこれが出る)。提案の案は `.dc.html` の `<title>` の先頭にも「(提案)」を置く。清書キャンバスへ写すときも名前を変えない (spec・ledger・写しのパスが指す名前を変えないため)
- ユーザーがそのラウンドを見る前の描き直しは同じ名前に上書きし、見たあとに描き直す案は新しい名前にする (問いのアートボード・ledger・spec が指した名前の中身を変えない)
- 同じ問いの案は同じ場面 (同じ画面・同じダミーデータ) で描き、問いで比べる差だけを変える
- 画面の移り変わりは、アートボード間のプロトタイプリンク (`<a href="share-card-link-R5-Q1-A-2.dc.html">`) で描く。`mock-evaluator` はこのリンクと行の並びで導線を辿る
- 値の問い (余白・件数など) で比べる値は、案のアートボードの `data-props` に Tweaks として宣言し (`{"cardGap":{"editor":"range","default":12,"min":8,"max":24,"step":4,"unit":"px"}}`)、`renderVals()` で `this.props.cardGap ?? 12` と読む。問いのアートボードはこの prop に値を渡して案を描き直す
- アートボードの HTML を書くのはサブエージェント (spec Step 3 の委任)。書き出し先は `docs/crystallize/specs/<slug>/design/round-<n>/`。親はこのファイルと Design 型が返した指示、名前と寸法、場面、値の問いで渡す prop の名前、前のラウンドの読み戻し (`design/round-<m>/project/`) の場所を渡す。サブエージェントはキャンバスに触らない
- 公開は親が行う (Artifact ツール、`url` = キャンバス)。アートボードのファイルと、それを載せた `canvas.json` は同じ公開の呼び出しで送る (Design 型は `canvas.json` に載っていない `.dc.html` も表示するため、別々に送ると途中の状態が見える)
- `canvas.json` は送る直前に `action: "read"` + `path: "project/canvas.json"` で読み直し (`url` だけの `read` はページしか返さない)、自分の項目だけを足し替えて送る。先に誰かが保存していると公開は拒否されるので、読み直してやり直す。3 回拒否されたらユーザーに伝えて止める

## 案出しキャンバス

- **作る時期**: その spec で初めて絵を描くラウンド。題は `<プロジェクト名> <slug> 案出し`
- 作る前に Artifact ツールの `action: "list"`, `type: "Design"`, `limit: 200` で同じ題を探し、見つかればそれを使う (記録は ledger の中にあるので、記録が main に入る前に切った worktree や並行するセッションからは見えないため)。同じ題が複数あればユーザーにどれを使うか聞く。見つからなければ `type_url` と題で publish して作り、返ってきた Design 型の指示 (ファイルの形、公開の仕方、先に読むページ) を読む
- **記録**: ledger の冒頭に `- 案出しキャンバス: <URL>` の 1 行を書く
- ページは分けない。ラウンドごとに帯を 1 つ作り、新しいラウンドを下に足す (前のラウンドの帯はそのまま残す)。帯の先頭に付箋「R<round>」(`title1`)、その下に**絵の要る問い 1 つ = 1 行**で、行頭に付箋「Q<n> <題>」(`title1`。アートボードが 1 枚なら `kind` 無しの付箋に `w` を付ける)、右に選択肢ごとのアートボードを 1 枚ずつ並べる。問いのアートボードは、その帯のいちばん長い行の右に置く。付箋の id は `R<round>` と `R<round>-Q<n>`
- **読み戻し**: 公開後、そのラウンドの各アートボード (問いのアートボードを含む) と `canvas.json` を `action: "read"` + `paths: ["project/<名前>.dc.html", …, "project/canvas.json"]` + **`out_dir` = `docs/crystallize/specs/<slug>/design/round-<n>` の絶対パス**で読み戻す。`out_dir` を省くと scratchpad に落ちる。ファイルは `<out_dir>/project/<名前>.dc.html` に入る。`mock-evaluator` と試問はこのディレクトリを読む (問いのアートボードだけは、試問を公開の前の版で行う。Gotchas の「読み戻しを省かない」)。スクリーンショットは撮らない
- **後始末**: spec の終了時 (Step 5) に「案出しキャンバスを消しますか」と 1 行聞き、ユーザーが消すと答えたときだけ Artifact ツールの `action: "delete"` で消す。消したら ledger の記録の行の末尾に「(削除済み)」と書く。消さないと答えたら残す (非公開のまま)。経緯は各ラウンドの読み戻しと ledger に残る

## 問いのアートボード

画面のあるタスクで、絵の要る問いがあるラウンドの問いは、ラウンドレポートではなく案出しキャンバスの**問いのアートボード**に置く (絵の要る問いが無いラウンドはラウンドレポート。spec Step 2)。案を横に見ながら答えられ、値の問いはその値で描き直した案をその場で見られる。

- 1 ラウンド 1 枚。名前は `<slug>-R<round>-ask` (ファイルは `project/share-card-link-R5-ask.dc.html`)、`boards` の `title` は `R<round> の問い`、`"is_interactive": true` を付ける
- **作り方**: このスキルの `assets/ask-board.dc.html` を写し、script の `data()` の中身、`<title>` (`R<round> の問い`)、右の列 (下記)、ルートの幅と `$preview` の幅・高さだけを書き替える。返信文を組む script と左の列のマークアップには触らない。雛形が扱うのは、問いの定義の 2 つの形 (radio と `kind: "range"`) だけ。`lede` は「このラウンドで決めること: N 問」の 1 行だけで、返信の仕方の案内は雛形が足す。`data()` の中身は spec Step 2 の問いの定義そのもの (`board` = 名前、`title` = `<slug> — 第 <round> ラウンド`、`lede`、`questions[{id, title, question, recommended, reason, options[{id, label, board}]}]` と値の問いの `kind: "range"` / `min` / `max` / `step` / `value` / `unit`、`assumed`)。選択肢の `board` には、その案の先頭のアートボードの `title` (`R5-Q1-A`) を書く。認識ラウンドの問いは `recommended` / `reason` を書かない (どれも選ばれていない状態で出る)。問いの文言を変えないため、書くのは親 (試問と質問監査はこの文言で行われる)
- **値の問いのプレビュー**: 右の列に、値の問いごとに見出し 1 行と `<dc-import name="<案のアートボード名>" <prop をケバブケースにした名前>="{{ vals.<問いの id> }}" hint-size="<幅>px,<高さ>px"></dc-import>` を 1 つずつ書く (雛形の `Q2 の値で描き直した案` のブロックを写して直す)。案の側にその prop が宣言されていること (両方に共通すること)。値の問いが無ければ右の列を消し、ルートの幅と `$preview` の幅を 560 にする。あれば幅は 496 + 32 + プレビューの幅 + 64
- 高さは中身が収まる値にし (切れるより縦に長いほうがよい)、`canvas.json` の `h` と `$preview` の高さを揃える
- アートボードには、今の答えから作った返信文 (`## Decisions` / `## Comments`) が出る。形はラウンドレポートの返信と同じで、読み方は spec Step 2 のまま。ただし `_(not opened; default kept)_` は出さず、触っていない問いは `_(kept as proposed)_` になる (問いが 1 枚に並び、返信欄はその下にあるため)。radio には「どれでもない・一部変えたい」、range には「この問いでは決められない」が付き、選ぶと複数行の入力欄が出る。「問わずに決めたこと」は閉じた節で、行をチェックすると入力欄が出て、返信の `## Comments` に「問わずに決めたこと」の見出しで載る
- ユーザーはこのアートボードを Play にして答え、「返信をコピー」(使えない環境では文を選んでコピー) でチャットに貼る。Play にできるのは同時に 1 枚だけなので、動く案を触ったあとは問いのアートボードを Play にし直す。答えはブラウザの localStorage に `crystallize-ask:<名前>:<問いの中身から作った印>` で残り、ブラウザをまたいでは共有されない。問いや `assumed` を直して公開し直すと印が変わり、答えは空から始まる (前の答えが別の問いや行に付かないため)
- **型の指示との関係**: Design 型の指示は、選択肢や理由をアートボードでなく返信に書き、調整は Tweaks にして widget を置かず、質問は AskUserQuestion で行うとしている。問いのアートボードはデザインではなく回答用紙なので、この 1 枚だけを例外とする。案のアートボードには型の指示をそのまま当てる。型が変わって問いのアートボードで答えられなくなったら (入力できない、返信文が出ないなど)、ラウンドレポートに戻す (spec Step 2)
- `mock-evaluator` の評価対象にしない (`-ask.dc.html` は読み飛ばされる)

## 清書キャンバス

- `docs/crystallize/design-canvas.md` に URL・Design 型の `type_url`・題・使ったデザインシステム (無ければ「なし」)・作成日を書く。題は `<プロジェクト名> design`。全 spec で同じキャンバスを使い、spec ごとにページを 1 つ足す。清書キャンバスを spec ごとに作らない (前に決めた画面との見比べができなくなる)
- `design-canvas.md` が無くても、すぐには作らない。先に `action: "list"`, `type: "Design"`, `limit: 200` で題 `<プロジェクト名> design` のキャンバスを探し、見つかればそれを使って URL と `type_url` を記録する。同じ題が複数あればユーザーにどれを使うか聞く。見つからなければ `type_url` と題で publish して作り、記録する
- **書く時期**: spec の終了時と、改訂のときだけ。ラウンドの途中では書かない
- spec 1 つにページ (`canvas.json` の `pages`) を 1 つ作る。`id` と `name` はどちらも slug。ページは 1 キャンバスに 40 個までなので、足せないときはユーザーにどの spec のページを片付けるか聞く。この spec のアートボードにはすべて `"page": "<slug>"` を付ける (付けないと最初のページに入る)。ページの中は確定したアートボードだけを、問いの順に横に並べる。帯や「(確定)」の印は置かない
- 自分の spec のページとアートボードだけを変える。`pages` と `order` は全 spec で 1 つの配列なので、自分の項目だけを足し引きし、残りはそのまま残す。この spec のものかどうかは名前の接頭辞ではなく `page` が slug かどうかで見分ける (`share-card` と `share-card-link` は接頭辞では区別できない)。ほかの spec のものと `launch` には触らない
- 以前の形 (共有の 3 ページ「今回の確認」「決まっていること」「不採用」、または slug のページの中の 3 つの帯) が残るキャンバスでは、それらには触らず、新しい spec から新しい形を使う

### 終了時に写す手順

1. 確定したアートボードを案出しキャンバスから `action: "read"` + `paths` + `out_dir` = `docs/crystallize/specs/<slug>/design` の絶対パスで読み戻し、`design/project/<名前>.dc.html` に置く (**写し**)
2. 写しの中に、清書に写さないアートボードへのリンク (`<a href>`) や `<dc-import>` があれば、サブエージェントに外させる (行き先が清書キャンバスに無くなるため)。ほかは直さない
3. 清書キャンバスの `canvas.json` を読み直し、この spec のページ・アートボード・`order` の項目を足して、写しと一緒に 1 回の公開で送る
4. 送ったアートボードを清書キャンバスから同じ `out_dir` で読み戻し、写しを清書キャンバスの中身と同じにする

- 実装者 (`code-generator`) は写しを読む。写しと清書キャンバスが食い違ったら清書キャンバスが正本で、写しを読み戻し直す
- 改訂 (挙動ゲートでの外観変更) では、サブエージェントが写しを直し、親が `read` (url) で清書キャンバスを開いてから再公開し、写しを読み戻す。案出しキャンバスは使わない (消えていることがある)

## Gotchas

- **清書キャンバスに案出しを持ち込まない** — 落ちた案・問いのアートボード・ユーザーに見せる前の版は送らない。清書キャンバスにあるのは確定したアートボードだけ
- **案をレポートに描かない** — 画面のないタスクのラウンドレポートにも、キャンバスが使えないときのラウンドレポートにも、案の絵を HTML で描かない。絵の正本はキャンバス
- **問いのアートボードの返信文を組む script と左の列を書き替えない** — 返信文の形はラウンドレポートの返信と揃えてあり、spec Step 2 の読み方はこれに依っている。書き替えてよいのは「作り方」に挙げた箇所だけ
- **読み戻しを省かない** — `mock-evaluator`・試問・写しが見るのは、キャンバスから読み戻したファイル。ローカルのファイルを直接渡すと、公開に失敗した案や古い版を見せることがある。例外は問いのアートボードで、試問は公開の前に親が `design/round-<n>/project/` に書いた版で行い、通ってから公開して読み戻す (試問の前にユーザーの開いているキャンバスへ問いが出ないため)
- **案出しキャンバスを黙って消さない** — 消すのはユーザーが消すと答えたときだけ。消すと元に戻せず、リンクも使えなくなる
